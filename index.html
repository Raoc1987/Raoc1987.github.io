ALKMIA

Training platform with an adaptive periodization engine. Solo project, live. Private code — this is a case study. Plataforma de treino com um motor de periodização adaptativo. Projeto individual, em produção. Código privado — isto é um caso de estudo.

An athlete logs every set. The app builds a training program, follows how it is executed, and adjusts the next weeks to what was really done.

The central decision: AI chooses which exercises. The engine decides how much. Sets, reps, load, progression and deload are calculated by a deterministic engine — reproducible and auditable. The language model (Claude) only selects exercises, and its answer is validated before use. No athlete plan depends on the model being right.

O atleta regista cada série. A app cria um programa de treino, acompanha a sua execução e ajusta as semanas seguintes ao que foi realmente feito.

A decisão central: a IA escolhe quais exercícios. O motor decide quanto. Séries, repetições, carga, progressão e deload são calculados por um motor determinístico — reprodutível e auditável. O modelo de linguagem (Claude) só escolhe exercícios, e a resposta é validada antes de ser usada. Nenhum plano depende de o modelo acertar.

How it is builtComo está construído

Immutable history. Programs are versioned. Regenerating creates a new version and never deletes the past. The app never writes a value the athlete did not record: an empty field is the truth, an estimated value is fiction.

Security in the database. Every row belongs to its owner, and PostgreSQL enforces it, not the application code. An integration test runs the real migrations and fails if any table loses its security policy.

Learning from what was done. Volume limits for each muscle group (MEV, MAV, MRV) are recalculated from executed volume, never from prescribed volume. Learning from your own prescription is a closed loop.

Atomic changes. A new program version is saved by one transactional database function. If any step fails, nothing is saved.

Histórico imutável. Os programas são versionados. Regenerar cria uma versão nova e nunca apaga o passado. A app nunca grava um valor que o atleta não registou: um campo vazio é a verdade, um valor estimado é ficção.

Segurança na base de dados. Cada linha pertence ao seu dono, e quem o impõe é o PostgreSQL, não o código da aplicação. Um teste de integração corre as migrações reais e falha se alguma tabela perder a sua política de segurança.

Aprender com o que foi feito. Os limites de volume de cada grupo muscular (MEV, MAV, MRV) são recalculados a partir do volume executado, nunca do prescrito. Aprender com a própria prescrição é um circuito fechado.

Alterações atómicas. Uma nova versão do programa é gravada por uma única função transacional na base de dados. Se algum passo falhar, nada é gravado.

The learning that learned nothingA aprendizagem que não aprendia

Symptom
None. The database column was filled, the audit log had a row, and the screen said "your limits were adjusted".
Reality
The writer saved keys like peito. The engine read Peito. The new values were never used.
Fix
Moved the logic into a pure, testable function. Added a test over every muscle group: each key must map to a label the engine reads.
Lesson
Three positive signals can point to a false conclusion. Found by audit, before real users depended on it.
Sintoma
Nenhum. A coluna estava preenchida, o registo de auditoria tinha uma linha e o ecrã dizia "os teus limites foram ajustados".
Realidade
Quem escrevia gravava chaves como peito. O motor lia Peito. Os valores novos nunca eram usados.
Correção
Passei a lógica para uma função pura e testável. Acrescentei um teste sobre todos os grupos musculares: cada chave tem de corresponder a um rótulo que o motor lê.
Lição
Três sinais positivos podem apontar para uma conclusão falsa. Encontrado por auditoria, antes de utilizadores reais dependerem disso.

One more training day made the plan worseMais um dia de treino piorava o plano

Symptom
A generic warning: "some groups are below minimum volume".
Reality
The weekly split repeated a 3-day cycle with i % 3. With 5 days it was cut in the middle: legs once per week, at 42% of the minimum effective volume. With 4 or 6 days, legs got two sessions.
Fix
An explicit table per number of days, plus a rule tested for 1 to 7 days: every large muscle group is trained at least twice a week when possible.
Lesson
A warning that treats an 8% gap and a 58% gap the same is noise, not a warning.
Sintoma
Um aviso genérico: "alguns grupos estão abaixo do volume mínimo".
Realidade
A divisão semanal repetia um ciclo de 3 dias com i % 3. Com 5 dias era cortado a meio: pernas uma vez por semana, a 42% do volume mínimo eficaz. Com 4 ou 6 dias, pernas tinham duas sessões.
Correção
Uma tabela explícita por número de dias, mais uma regra testada de 1 a 7 dias: todo o grupo muscular grande é treinado pelo menos duas vezes por semana quando possível.
Lição
Um aviso que trata igual uma falta de 8% e uma de 58% é ruído, não é aviso.

A feature that existed only on paperUma funcionalidade que só existia no papel

Symptom
None. Documents described continuous learning as working.
Reality
The table of learned limits was read, but nothing ever wrote to it. The code fell back to reasonable default values. Nothing failed.
Fix
Connected the writer and added audit records for every end of training week.
Lesson
A column is alive only when something writes to it — in the same vocabulary its readers use. Check the code, not the status document.
Sintoma
Nenhum. A documentação descrevia a aprendizagem contínua como funcional.
Realidade
A tabela de limites aprendidos era lida, mas nada escrevia nela. O código caía em valores por omissão razoáveis. Nada falhava.
Correção
Liguei quem escreve e acrescentei registos de auditoria em cada fim de semana de treino.
Lição
Uma coluna só está viva quando alguém escreve nela — no mesmo vocabulário de quem a lê. Verificar o código, não o documento de estado.

How I workComo trabalho

  • Diagnose before fixing. Read the real error message before changing anything.
  • Check the object, not the log. To know what the database has, query the database.
  • Never swallow an error. A hidden error is paid for later, in hours.
  • Implemented is not verified. Every status claim says how it was checked.
  • Diagnóstico antes da correção. Ler a mensagem de erro real antes de mudar seja o que for.
